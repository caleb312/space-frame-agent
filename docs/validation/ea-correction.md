# 仅给EA的桁架与纠正入口修复（2026-10-11）

用户图I-8的纠正曾连续两次返回invalid。归档`20261011_151841_881624.json`中的诊断显示：
第一次把独立E和A当作parameter_inputs单项，缺少圆截面必填字段；第二次又给出不支持的material_type/section_type和单位。
根因是PATCH_SYSTEM要求所有材料变化进入仅支持实心圆E/ν/R的参数接口，而且纠正工具嵌套Schema只有空object。
这不是用户自然语言纠正不合规，也不是额度/网络故障。

修复：

- 纠正工具公开实际RecognitionPatch嵌套Schema，并带原生结构类型规则。
- 用户直接给E/A/I，用facts更新，保留user_given/user来源；不要求虚构ν/R。
- 仅给EA时使用AxialRigidityInput，原值、单位、来源均显式记录。
- Python转换N/kN，等效取A=1m²、E=EA/A，保持题给EA，仅允许平面/空间桁架；不代表真实截面，不可用于应力推断。
- EA冲突、模型类型不适用、真实物性与计算值冲突继续阻止求解。不同EA应分配独立等效材料/截面管理编号。
- 原有实心圆工具和刚度组装、坐标变换、LDLT、内力恢复算法不变。
- 不再把未知E/A同时列作缺失两遍；实际EA等效假定在模型核对表显示。
- 无效纠正展示具体路径及错误，连续失败说明是Agent工具参数错误，仍保留重试上限和用户确认。
- 顺手修正桁架结果概要为“各杆轴力”。

本轮全套126项测试通过，含7项新增EA/纠正回归；网页脚本语法检查通过。
见`results/ea_correction_test_run.txt`。真实Qwen的新Schema遵循仍待下一次用户请求验证。

## 可选列表格式兼容修复

后续确认坐标时，questions与parameter_inputs两次因非列表类型被拒绝。已保存诊断没有包含供应商原始参数值，因此不推断具体是空串还是序列化数组。
工具Schema现在对这些可选数组直接显示type=array/items，未修改字段要求省略。
安全兼容处理仅解码合法JSON数组字符串、将单个完整参数对象包成数组、省略未修改的空白字符串；随后仍走原有严格成员校验。
空白字符串不会当作[]，以免清空旧问题和EA。非空自然语言、数字、布尔、不合法参数成员仍拒绝。
